SkyCore Guide: Set Up Azure Cobalt 200 VMs for AI Workloads in SMBs

In today's competitive landscape, even small to medium-sized businesses (SMBs) are recognizing the transformative potential of Artificial Intelligence (AI). From enhanced customer service chatbots to predictive analytics and intelligent automation, AI can unlock significant operational efficiencies and new revenue streams. However, deploying AI workloads often demands robust, cost-effective compute infrastructure. This is where Azure Cobalt 200 VMs emerge as a game-changer for SMBs. These ARM-based virtual machines, powered by Microsoft's custom-designed Cobalt 200 processors, offer a compelling balance of performance, efficiency, and cost, particularly for CPU-bound AI inference, data preprocessing, and model development. By the end of this comprehensive SkyCore Solutions guide, you will have successfully provisioned and configured an Azure Cobalt 200 VM, ready to host your initial AI workloads in a secure and cost-efficient manner.

Prerequisites

  • An active Azure subscription (free trial or paid)
  • Contributor role or higher in the Azure subscription
  • Azure CLI installed (version 2.50.0 or higher) and authenticated
  • A local SSH client (e.g., OpenSSH on Windows/Linux/macOS)
  • Basic understanding of virtual machines and networking concepts
  • Estimated Cost: ~$150-300 USD/month for a Standard_D8ps_v5 VM running 8 hours a day (costs vary significantly by region, actual usage, and whether Spot instances are used).

Step 1: Authenticate with Azure CLI

Before provisioning any resources, you must authenticate your local Azure CLI session with your Azure subscription. This establishes a secure connection and grants the CLI the necessary permissions to manage your Azure resources.

az login
  • az login: Initiates the authentication process. It will typically open a web browser for you to sign in with your Azure credentials.

Portal alternative: Sign in directly to the Azure portal.

Run this to verify: After successful authentication, your default subscription details will be displayed. You can also list your subscriptions to confirm:

az account list --output table

Step 2: Create a Resource Group

A resource group is a logical container for your Azure resources. Grouping related resources like your VM, network, and storage accounts simplifies management, monitoring, and cleanup of your Azure Cobalt 200 VM and related components. This approach is highly recommended for SMBs to maintain order and cost control.

az group create \
    --name "SkyCoreAIGroup" \
    --location "eastus"
  • --name "SkyCoreAIGroup": Specifies the name for your new resource group. Choose a descriptive name, perhaps reflecting your company or project.
  • --location "eastus": Defines the Azure region where the resource group metadata will be stored. It's best practice to select a region geographically close to your users or other Azure services you plan to connect, to minimize latency. For AI workloads, consider regions with good network connectivity and potentially lower compute costs.

Portal alternative:

  1. Sign in to the Azure portal.
  2. In the search bar, type "Resource groups" and select it.
  3. Click + Create.
  4. Enter SkyCoreAIGroup for the Resource group name.
  5. Select East US for the Region.
  6. Click Review + create, then Create.

Run this to verify: Confirm the resource group has been created:

az group show --name "SkyCoreAIGroup" --output table

Step 3: Provision an Azure Cobalt 200 VM for AI Workloads

This is the core step where we deploy our ARM-based Azure Cobalt 200 VM. Azure Cobalt 200 VMs, indicated by the 'p' suffix in their size name (e.g., Dps_v5), are Microsoft's custom ARM processors designed for excellent performance per watt. For SMBs, these VMs are ideal for CPU-intensive AI inference, data processing, backend services for AI applications, and even light to medium model training where dedicated GPUs are not yet justified. We will select an Ubuntu Server 22.04 LTS Gen2 image, which is well-suited for AI development environments due to its widespread support and ecosystem.

az vm create \
    --resource-group "SkyCoreAIGroup" \
    --name "SkyCoreAICobaltVM" \
    --image "Ubuntu2204Gen2" \
    --size "Standard_D8ps_v5" \
    --admin-username "azureuser" \
    --generate-ssh-keys \
    --public-ip-address-sku "Standard" \
    --zone 1 \
    --priority "Spot" \
    --eviction-policy "Deallocate" \
    --tags Environment=AI-Dev Project=SkyCoreSMB
  • --resource-group "SkyCoreAIGroup": Specifies the resource group created in the previous step.
  • --name "SkyCoreAICobaltVM": Assigns a name to your new virtual machine.
  • --image "Ubuntu2204Gen2": Selects the operating system image. Ubuntu Server 22.04 LTS (Gen2) is recommended for its stability and broad support for AI development tools.
  • --size "Standard_D8ps_v5": This is where we select the Azure Cobalt 200 VM. The 'p' indicates an ARM-based processor. Standard_D8ps_v5 offers 8 vCPUs and 32 GiB of memory, providing a solid foundation for many SMB AI workloads without over-provisioning. Other Cobalt options like Standard_D16ps_v5 or Standard_E8ps_v5 (memory-optimized) are also available depending on your specific needs.
  • --admin-username "azureuser": Sets the username for the administrator account on the VM.
  • --generate-ssh-keys: Automatically generates a new SSH public/private key pair. The private key will be saved locally in ~/.ssh/. This is the recommended secure authentication method.
  • --public-ip-address-sku "Standard": Uses a Standard SKU public IP address, which offers enhanced security features like DDoS protection and better availability compared to Basic.
  • --zone 1: Deploys the VM into an Availability Zone. For SMBs, deploying into a single zone is often sufficient for development or non-critical workloads, offering resilience against datacenter-level failures within that zone. For higher availability, consider multiple zones or an availability set.
  • --priority "Spot": Designates this VM as a Spot instance. Spot VMs leverage unused Azure capacity and can result in significant cost savings (up to 90% off pay-as-you-go prices) for fault-tolerant AI development or test workloads.
  • --eviction-policy "Deallocate": If the Spot VM is evicted due to capacity demands, this policy deallocates it instead of deleting it, allowing you to restart it later.
  • --tags Environment=AI-Dev Project=SkyCoreSMB: Applies custom tags for better resource organization and cost analysis, crucial for SMBs tracking project spending.
Pro tip: For production AI inference services that require guaranteed uptime, avoid --priority "Spot" and deploy a regular pay-as-you-go VM. Spot VMs are excellent for development, testing, and batch processing where interruptions are acceptable.

Portal alternative:

  1. Sign in to the Azure portal.
  2. Search for "Virtual machines" and select it. Click + Create, then Azure virtual machine.
  3. On the Basics tab:
    • Subscription: Select your Azure subscription.
    • Resource group: Choose SkyCoreAIGroup.
    • Virtual machine name: Enter SkyCoreAICobaltVM.
    • Region: Select East US.
    • Availability options: Select Availability zone and choose 1.
    • Security type: Standard.
    • Image: Select Ubuntu Server 22.04 LTS Gen2.
    • Azure Spot instance: Select Yes, then Deallocate for Eviction type.
    • Size: Click See all sizes, then filter or search for D8ps_v5 and select Standard_D8ps_v5.
    • Authentication type: SSH public key.
    • Username: azureuser.
    • SSH public key source: Generate new key pair, enter myCobaltKey for Key pair name.
    • Public inbound ports: Select Allow selected ports, then choose SSH (22).
  4. Go to the Tags tab, add Environment with value AI-Dev and Project with value SkyCoreSMB.
  5. Click Review + create. Review the details, then click Create. Download your private key when prompted.

Run this to verify: Get the public IP address of your new VM:

az vm show \
    --resource-group "SkyCoreAIGroup" \
    --name "SkyCoreAICobaltVM" \
    --query "publicIps" \
    --output tsv

Step 4: Configure Network Security Group (NSG) for AI Access

While SSH (port 22) is open by default for management, your AI workloads might require additional ports. For example, if you're running a Jupyter Notebook server (often port 8888), a custom REST API (e.g., port 5000), or a web application for showcasing AI results (e.g., port 80 or 443), you'll need to open these ports in the Network Security Group (NSG) associated with your VM. We will demonstrate opening port 8888 for a common AI tool like Jupyter.

az vm open-port \
    --resource-group "SkyCoreAIGroup" \
    --name "SkyCoreAICobaltVM" \
    --port 8888 \
    --priority 1001 \
    --description "Allow Jupyter Notebook access"
  • --resource-group "SkyCoreAIGroup": The resource group containing your VM.
  • --name "SkyCoreAICobaltVM": The name of your Azure Cobalt 200 VM.
  • --port 8888: The inbound port to open. Adjust this to match the port required by your specific AI application.
  • --priority 1001: Sets the priority for the NSG rule. Lower numbers have higher priority. We pick a value greater than the default SSH rule (priority 1000) to ensure both rules are active.
  • --description "Allow Jupyter Notebook access": A descriptive note for the rule, aiding in future management.
Common pitfall: Overly permissive NSG rules can expose your VM to security risks. Only open ports that are strictly necessary and consider restricting source IP addresses (--source-address-prefixes parameter) to your office IP range for enhanced security. Never expose sensitive administrative ports directly to the internet without proper protections.

Portal alternative:

  1. In the Azure portal, navigate to your SkyCoreAICobaltVM.
  2. In the left menu, under Networking, select Networking.
  3. Click Add inbound port rule.
  4. For Destination port ranges, enter 8888.
  5. Set Priority to 1001.
  6. For Name, enter AllowJupyter.
  7. Click Add.

Run this to verify: List the inbound security rules for your VM's network interface:

az network nsg rule list \
    --resource-group "SkyCoreAIGroup" \
    --nsg-name "SkyCoreAICobaltVM-nsg" \
    --query "[?access=='Allow']" \
    --output table

Step 5: Connect to Your Cobalt VM and Install AI Dependencies

With your Azure Cobalt 200 VM provisioned and network access configured, it's time to connect via SSH and set up your AI development environment. This typically involves updating packages, installing Python, pip, and then the necessary AI frameworks. Keep in mind that for ARM-based systems, you'll need ARM-compatible versions of libraries, which are often available for popular frameworks.

First, retrieve your VM's public IP address (if you haven't already):

VM_IP=$(az vm show -d --resource-group "SkyCoreAIGroup" --name "SkyCoreAICobaltVM" --query "publicIps" -o tsv)

Now, connect to your VM:

ssh -i ~/.ssh/myCobaltKey_rsa azureuser@$VM_IP
  • -i ~/.ssh/myCobaltKey_rsa: Specifies the path to your private SSH key. Adjust myCobaltKey_rsa if you chose a different name during VM creation.
  • azureuser@$VM_IP: Uses the admin username and the public IP address of your VM to establish the SSH connection.

Once connected, proceed with installing common AI dependencies. For ARM-based VMs, ensure you're installing packages compatible with the `aarch64` architecture. Many Python packages automatically detect the architecture and install the correct wheel.

sudo apt update && sudo apt upgrade -y
sudo apt install -y python3-pip python3-venv
python3 -m venv ai_env
source ai_env/bin/activate
pip install --upgrade pip
pip install numpy pandas scikit-learn jupyterlab tensorflow-cpu  # tensorflow-cpu is often ARM-optimized
# For PyTorch, check official docs for ARM/aarch64 specific installation commands
# Example: pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cpu
  • sudo apt update && sudo apt upgrade -y: Updates your VM's package lists and upgrades installed packages to their latest versions.
  • sudo apt install -y python3-pip python3-venv: Installs Python's package installer (pip) and tools for creating isolated Python environments (venv), which is a best practice for AI projects.
  • python3 -m venv ai_env: Creates a new virtual environment named `ai_env`.
  • source ai_env/bin/activate: Activates the virtual environment.
  • pip install --upgrade pip: Ensures your pip version is up-to-date.
  • pip install numpy pandas scikit-learn jupyterlab tensorflow-cpu: Installs fundamental AI/data science libraries. Note tensorflow-cpu for CPU-only inference. For PyTorch, verify their official website for ARM-specific installation instructions as it can vary.

Portal alternative: There is no direct portal equivalent for installing software inside the VM. You must connect via SSH as described above.

Run this to verify: After installation, check the versions of your installed tools:

(ai_env) python3 -c "import tensorflow as tf; print(tf.__version__)"
(ai_env) jupyter lab --version
Pro tip: For advanced MLOps or continuous integration/deployment (CI/CD) pipelines, consider using Azure DevOps or GitHub Actions to automate the setup and deployment of your AI environments and models on these Cobalt VMs.

Step 6: Implement Cost Management with Auto-shutdown

For SMBs, managing cloud costs is paramount. Azure's Auto-shutdown feature for VMs is a simple yet effective way to prevent unnecessary charges by automatically stopping your Azure Cobalt 200 VM during off-hours, ensuring you're only billed for compute when it's actively in use. This is particularly valuable for development or staging AI environments.

az vm auto-shutdown \
    --resource-group "SkyCoreAIGroup" \
    --name "SkyCoreAICobaltVM" \
    --time "2000" \
    --webhook "" \
    --email "" \
    --enabled true
  • --resource-group "SkyCoreAIGroup": The resource group containing your VM.
  • --name "SkyCoreAICobaltVM": The name of your Azure Cobalt 200 VM.
  • --time "2000": Sets the daily shutdown time in UTC (24-hour format). Here, 2000 means 8:00 PM UTC. Adjust this to your local timezone equivalent for when the VM should shut down.
  • --webhook "": (Optional) A webhook URL to notify external systems before shutdown.
  • --email "": (Optional) An email address to send a notification before shutdown.
  • --enabled true: Activates the auto-shutdown feature.

Portal alternative:

  1. In the Azure portal, navigate to your SkyCoreAICobaltVM.
  2. In the left menu, under Operations, select Auto-shutdown.
  3. Set Enable to On.
  4. Adjust the Scheduled shutdown time (remember this is UTC).
  5. Optionally, configure email notifications or a webhook.
  6. Click Save.

Run this to verify: Check the auto-shutdown configuration for your VM:

az vm auto-shutdown show \
    --resource-group "SkyCoreAIGroup" \
    --name "SkyCoreAICobaltVM" \
    --output table
