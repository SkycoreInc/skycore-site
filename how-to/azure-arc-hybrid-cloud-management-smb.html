Your Essential Azure Arc Hybrid Cloud Management Guide for SMBs

In today's dynamic business landscape, Small and Medium-sized Businesses (SMBs) often find themselves juggling infrastructure across on-premises data centers, multiple cloud providers, and even edge devices. This fragmented approach leads to operational complexity, inconsistent security policies, and increased management overhead. SkyCore Solutions understands these challenges, and we believe Azure Arc is the transformative solution for SMBs. This Azure Arc hybrid cloud management guide will walk you through the process of extending Azure's robust management capabilities to your existing non-Azure resources, unifying your IT environment under a single pane of glass. By the end of this guide, you will have successfully onboarded your hybrid servers and potentially a Kubernetes cluster to Azure Arc, enabling consistent governance, monitoring, and security across your entire estate.

Prerequisites

  • An active Azure subscription. For management operations, your Azure user account needs the 'Contributor' or 'Owner' role at the subscription or resource group level.
  • Azure CLI installed and configured on your workstation (version 2.x or later).
  • PowerShell 5.1 (for Windows) or PowerShell Core (for Linux/macOS) installed, with the Azure Az module.
  • Target Windows or Linux server (physical or virtual machine) with outbound internet connectivity to Azure endpoints. Ensure the server meets the Azure Connected Machine agent prerequisites.
  • For Kubernetes integration (optional for SMBs starting with containers): A running Kubernetes cluster (any CNCF-certified distribution) with kubeconfig access and outbound internet connectivity.
  • Estimated cost: The core Azure Arc control plane functionality (resource organization, RBAC, searching, automation templates) is offered at no extra cost. However, any Azure services you enable on your Azure Arc-enabled resources, such as Azure Monitor, Microsoft Defender for Cloud, or Azure Automation, will incur charges based on their respective pricing models. It's crucial for SMBs to monitor these costs via Azure Cost Management.

Step 1: Prepare Your Azure Environment

Before connecting your hybrid machines, we need to ensure your Azure environment is ready. This involves logging into your Azure subscription and creating a dedicated resource group to house your Azure Arc-enabled resources. Using a specific resource group helps with organization, access control, and cost management, which are vital for SMBs.

az login
az account set --subscription "Your Azure Subscription Name or ID"
az group create --name "SkyCore-Arc-Resources" --location "eastus"
  • az login: Opens a browser window for you to authenticate with your Azure account.
  • az account set --subscription "Your Azure Subscription Name or ID": Selects the specific Azure subscription you'll be working with. Replace with your actual subscription name or ID.
  • az group create --name "SkyCore-Arc-Resources" --location "eastus": Creates a new resource group named SkyCore-Arc-Resources in the eastus region. We recommend choosing an Azure region geographically closest to your on-premises servers to minimize latency and comply with potential data residency requirements.

Portal alternative: Navigate to the Azure portal (portal.azure.com), search for "Resource groups", and click "Create". Provide a subscription, resource group name (e.g., SkyCore-Arc-Resources), and choose a region (e.g., East US).

Run this to verify:

az group show --name "SkyCore-Arc-Resources" --output table

Step 2: Onboard a Hybrid Server Using Azure Arc Deployment Script

This is the core of our Azure Arc hybrid cloud management guide for servers. Connecting your physical servers or virtual machines (Windows or Linux) to Azure Arc involves installing the Azure Connected Machine agent. For SMBs, the most efficient and recommended method for a small number of servers is to use the deployment script generated from the Azure portal. This script automates the download, installation, and initial configuration of the agent, ensuring a smooth onboarding process.

For Windows Servers:

az connectedmachine create-script --resource-group "SkyCore-Arc-Resources" --location "eastus" --machine-name "YourWindowsServer" --os-type "Windows" --output "script" > onboard-windows.ps1
  • az connectedmachine create-script: This command generates the PowerShell script to onboard a Windows server.
  • --resource-group "SkyCore-Arc-Resources": Specifies the resource group where the Arc-enabled server will be managed.
  • --location "eastus": The Azure region for the Arc resource. This should ideally match your chosen resource group location.
  • --machine-name "YourWindowsServer": A unique name for your server as it will appear in Azure Arc. Choose a descriptive name.
  • --os-type "Windows": Specifies the operating system.
  • --output "script" > onboard-windows.ps1: Directs the output to a PowerShell script file named onboard-windows.ps1.

Once the script is generated, copy its content to your Windows server. Open PowerShell as Administrator on the target server and execute the script:

.\onboard-windows.ps1
Common pitfall: Ensure your server has outbound connectivity to Azure endpoints (specifically *.service.microsoft.com and *.blob.core.windows.net). If your SMB uses a proxy server, you'll need to configure proxy settings for the Azure Connected Machine agent. Refer to Microsoft's documentation for proxy configuration details to avoid connection failures.

For Linux Servers:

az connectedmachine create-script --resource-group "SkyCore-Arc-Resources" --location "eastus" --machine-name "YourLinuxServer" --os-type "Linux" --output "script" > onboard-linux.sh
  • az connectedmachine create-script: Generates the Bash script to onboard a Linux server.
  • --resource-group "SkyCore-Arc-Resources": The resource group for the Arc-enabled server.
  • --location "eastus": The Azure region.
  • --machine-name "YourLinuxServer": A unique name for your Linux server in Azure Arc.
  • --os-type "Linux": Specifies the operating system.
  • --output "script" > onboard-linux.sh: Directs the output to a Bash script file named onboard-linux.sh.

Transfer the onboard-linux.sh script to your Linux server. Open a terminal on the target server and execute it with root privileges:

sudo bash onboard-linux.sh

Portal alternative: In the Azure portal, search for "Azure Arc". Under the "Infrastructure" section, select "Machines". Click "Add" and then "Add a single server". Follow the wizard to select your subscription, resource group, region, OS type, and desired connectivity method (Public Endpoint for most SMBs). The portal will then generate the specific script for you to download and run on your target server.

Pro tip: Automatic SQL Server Connection: If your Windows or Linux server also has Microsoft SQL Server installed, Azure Arc can automatically connect these SQL Server instances to Azure Arc. This provides detailed inventory and additional management capabilities. If you wish to opt-out, add a tag to the server before onboarding with the name ArcSQLServerExtensionDeploy and value Disabled.

Step 3: Verify Azure Arc-enabled Server Connectivity and Management

After executing the deployment script on your hybrid server, it's crucial to verify that the Azure Connected Machine agent has successfully established communication with Azure Arc. This confirmation ensures that your server is now a first-class Azure resource, ready for unified management.

Run this to verify:

az connectedmachine show --name "YourWindowsServer" --resource-group "SkyCore-Arc-Resources" --output table
  • az connectedmachine show: Retrieves details about a specific Azure Arc-enabled server.
  • --name "YourWindowsServer": Replace with the actual name you assigned to your server.
  • --resource-group "SkyCore-Arc-Resources": The resource group containing your Arc-enabled server.

Look for the Status column in the output. It should display Connected. If it shows Disconnected or Expired, re-check network connectivity and agent logs on the server. The agent sends heartbeats every five minutes, and if no heartbeats are received for 15-30 minutes, the status changes to Disconnected. An Expired status occurs if the machine remains disconnected for 45 days, requiring a disconnect and reconnect procedure.

Portal alternative: Navigate to the Azure portal, search for "Azure Arc", and select "Machines" under the "Infrastructure" section. You should see your newly onboarded server listed with a "Connected" status. Click on the server name to view its detailed properties, extensions, and management options.

Step 4: Extend Management Capabilities with Azure VM Extensions

With your servers now Azure Arc-enabled, you can leverage Azure's extensive ecosystem of VM extensions to enhance monitoring, security, and configuration management – a key benefit of this Azure Arc hybrid cloud management guide for SMBs. This step demonstrates how you can deploy extensions, transforming your hybrid servers into fully managed Azure assets.

To install the Azure Monitor Agent for collecting logs and performance data:

az vm extension set \
  --publisher "Microsoft.Azure.Monitor" \
  --name "AzureMonitorWindowsAgent" \
  --type "AzureMonitorWindowsAgent" \
  --vm-name "YourWindowsServer" \
  --resource-group "SkyCore-Arc-Resources" \
  --settings "{}" \
  --enable-auto-upgrade true

Or for Linux:

az vm extension set \
  --publisher "Microsoft.Azure.Monitor" \
  --name "AzureMonitorLinuxAgent" \
  --type "AzureMonitorLinuxAgent" \
  --vm-name "YourLinuxServer" \
  --resource-group "SkyCore-Arc-Resources" \
  --settings "{}" \
  --enable-auto-upgrade true
  • az vm extension set: Command to install or update an extension on a VM (or Arc-enabled server).
  • --publisher "Microsoft.Azure.Monitor": Specifies the publisher of the extension.
  • --name "AzureMonitorWindowsAgent" / "AzureMonitorLinuxAgent": The name of the specific agent.
  • --type "AzureMonitorWindowsAgent" / "AzureMonitorLinuxAgent": The type of the extension.
  • --vm-name "YourWindowsServer" / "YourLinuxServer": The name of your Arc-enabled server.
  • --resource-group "SkyCore-Arc-Resources": The resource group.
  • --settings "{}": Initial settings for the extension. For Azure Monitor Agent, this can often be left empty as configuration is managed via Data Collection Rules (DCRs).
  • --enable-auto-upgrade true: Ensures the agent automatically updates to newer versions, reducing manual maintenance.

Portal alternative: In the Azure portal, navigate to your Arc-enabled server. Under the "Operations" section, select "Extensions + applications". Click "+ Add" and search for the desired extension (e.g., "Azure Monitor Agent" or "Log Analytics agent"). Follow the prompts to install it.

Run this to verify:

az connectedmachine extension show --machine-name "YourWindowsServer" --name "AzureMonitorWindowsAgent" --resource-group "SkyCore-Arc-Resources" --output table

Confirm the provisioningState is Succeeded.

Step 5: (Optional) Connect an Azure Arc-enabled Kubernetes Cluster

For SMBs embracing modern application development and containerization, Azure Arc extends its consistent management plane to Kubernetes clusters, regardless of where they run. This allows you to manage and govern your Kubernetes clusters at scale, deploy configurations using GitOps, and enforce compliance with Azure Policy – another powerful aspect of your Azure Arc hybrid cloud management guide.

az connectedk8s connect \
  --name "SkyCoreKubernetes" \
  --resource-group "SkyCore-Arc-Resources" \
  --location "eastus" \
  --correlation-id "your-correlation-id-here"
  • az connectedk8s connect: Initiates the connection of a Kubernetes cluster to Azure Arc.
  • --name "SkyCoreKubernetes": A unique name for your Kubernetes cluster as it will appear in Azure Arc.
  • --resource-group "SkyCore-Arc-Resources": The resource group where the Arc-enabled cluster will be managed.
  • --location "eastus": The Azure region for the Arc resource.
  • --correlation-id "your-correlation-id-here": (Optional) A unique identifier for tracking deployments. For SMBs, this can often be omitted unless specifically required for reporting.

When you run this command, it downloads and deploys the necessary Azure Arc agents (e.g., azure-arc-onboarding, cluster-agent) into your Kubernetes cluster. Ensure your kubeconfig is correctly configured to point to the target cluster before executing this command.

Portal alternative: In the Azure portal, search for "Azure Arc". Under the "Infrastructure" section, select "Kubernetes clusters". Click "+ Add", then "Connect a cluster". Choose your subscription, resource group, and region. Provide a cluster name and select the desired tags. The portal will then provide the exact CLI command to run on your workstation where kubeconfig for the target cluster is set.

Step 6: Verify Azure Arc-enabled Kubernetes Cluster Connectivity

Once the az connectedk8s connect command completes, it's essential to verify that your Kubernetes cluster is successfully registered with Azure Arc and its agents are running within the cluster. This confirms that Azure now has visibility and control over your containerized environment.

Run this to verify:

az connectedk8s show --name "SkyCoreKubernetes" --resource-group "SkyCore-Arc-Resources" --output table
  • az connectedk8s show: Retrieves details about a specific Azure Arc-enabled Kubernetes cluster.
  • --name "SkyCoreKubernetes": Replace with the actual name you assigned to your cluster.
  • --resource-group "SkyCore-Arc-Resources": The resource group containing your Arc-enabled cluster.

The output should show a connectivityStatus of Connected. You can also verify the agent deployments within your Kubernetes cluster:

kubectl get deployments -n azure-arc

You should see deployments like cluster-connectivity-agent and cluster-metadata-operator in the azure-arc namespace, indicating successful agent deployment.

Portal alternative: Navigate to the Azure portal, search for "Azure Arc", and select "Kubernetes clusters". Your newly connected cluster should appear with a "Connected" status. Clicking on the cluster name provides an overview, including agent status and deployed extensions.
